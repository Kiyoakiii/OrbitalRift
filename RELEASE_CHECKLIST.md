# Orbital Rift — release checklist

Этот список отделяет локальную debug-сборку от файла, который действительно можно отправлять в Google Play.

## Один раз для проекта

- Установить Unity `6000.3.22f1` с Android SDK, NDK и OpenJDK.
- Создать upload keystore, сохранить его вне репозитория и сделать резервную копию.
- В `Project Settings -> Player -> Android -> Publishing Settings` выбрать keystore и alias.
- Не добавлять в Git `.keystore`, `.jks`, пароли и локальные файлы Firebase CLI.
- Развернуть правила из `firebase/firestore.rules` согласно `FIREBASE_PRODUCTION.md`.
- Подготовить страницу политики конфиденциальности: игра использует анонимный Firebase UID, введённый позывной, рекорд, MMR и время обновления записи.
- Рекламные разрешения `AD_ID`, Attribution и Install Referrer явно удалены из объединённого Android Manifest, потому что в игре нет рекламы и рекламной атрибуции. После каждого обновления Firebase SDK повторно проверять разрешения готового APK; наличие самого Analytics всё равно нужно корректно отразить в Google Play Data Safety, если он остаётся включённым.

## Перед каждой версией

- Поднять `Bundle Version` и Android `Version Code`.
- Запустить `Orbital Rift -> Validate Product Readiness` без ошибок.
- Проверить готовый APK через `aapt dump badging`: есть одна `launchable-activity` с именем `com.unity3d.player.UnityPlayerActivity`.
- Проверить главное меню, ввод позывного, старт, обе зоны управления, паузу при сворачивании и возврат музыки.
- Доиграть до третьей фазы: проверить босса, Triple Shot, постоянный баф и purple solid shield.
- Проверить `TOP RECORD`, `TOP MMR`, изменение MMR после победы и поражения, а также понятный режим `OFFLINE` без падения игры.
- Проверить звук отдельно в режимах: всё включено, только музыка, только SFX, всё выключено.
- Проверить минимум на одном узком телефоне и одном планшете; убедиться, что safe area не режет UI и орбита остаётся внутри экрана.
- Провести co-op smoke test на двух клиентах: хост создаёт пати, клиент входит по коду, хост запускает сектор, оба корабля двигаются и получают одинаковое состояние комнат и seed.
- В co-op проверить командный корпус, авторитетный урон и поражение хоста, завершение всех комнат, отключение клиента и повторный вход по тому же коду пати.
- Собрать `Orbital Rift -> Build Android Release AAB`.
- Установить debug APK на физическое устройство и провести smoke test после чистой установки.

## Google Play internal testing

- Загрузить AAB во внутренний тестовый трек, а не сразу в production.
- Проверить отчёт pre-launch, Android Vitals и отсутствие новых crash/ANR.
- Пройти тест двумя разными устройствами/аккаунтами и убедиться, что обе записи видны в таблицах лидеров.
- После подтверждения повысить тот же артефакт из internal testing в следующий трек.

## Известная граница безопасности

Текущий клиент отправляет рекорд и MMR напрямую в Firestore. Правила ограничивают форму и резкий рост данных, но не доказывают честность сыгранного матча. Для публичного соревновательного релиза начисление MMR следует перенести в доверенный backend или Cloud Function с серверной проверкой результата.

## Последний проверенный прогон

- Дата: `2026-08-29`.
- Эмулятор профиля Samsung S9: `1440x2960`, Android API 37, портретная ориентация.
- Пройдены чистая установка, launcher Activity, меню, обязательный позывной, Firebase Anonymous Auth и обе глобальные таблицы лидеров.
- Пройден живой Relay-тест двух клиентов: Android-хост и Windows-клиент, `2/2` пилота, общий seed, синхронизация ввода, командный корпус, завершение `14/14` комнат, выход клиента и повторный вход.
- Производительность headless-эмулятора со SwiftShader не отражает GPU Samsung S9. Перед релизом остаётся обязательный тест FPS, памяти и звука на физическом устройстве.
- Release AAB намеренно заблокирован, пока владелец не настроит upload keystore и alias вне Git.
