# Боссы, мобы, выстрелы и баланс — руководство

Все изменения ассетов делай **вне Play Mode**, сохраняй Ctrl+S, затем запускай игру заново. Изменение ScriptableObject в Play может сохраниться, а некоторые параметры считываются только при появлении объекта: для воспроизводимого результата редактируй после Stop.

## Где что находится

| Что меняем | Ассет / папка в Project |
|---|---|
| Главные ссылки, пределы объектов, HP игрока/флагмана | `Assets/Resources/Gameplay/GameRules.asset` |
| Порядок боссов и обычных волн Classic | `Gameplay/ClassicSequence.asset` |
| Состав и порядок волн защиты | `Gameplay/DefenseSequence.asset` |
| Рост сложности, скорость, частота огня | `Gameplay/BalanceSettings.asset` |
| Орбита | `Gameplay/OrbitSettings.asset` |
| Эхо и скачок игрока | `Gameplay/OrbitalAbilitySettings.asset` |
| Подбираемый бонус | `Gameplay/BonusSettings.asset` |
| Корабли игрока, стихия и множители | `Gameplay/Ships/*.asset` |
| Рейтинг / громкость / масштаб камеры | `Gameplay/MmrSettings.asset`, `GameAudioSettings.asset`, `GameplayCameraZoomSettings.asset` |
| Кооперативные траектории, линзы, временные награды | `Gameplay/CoopTrajectorySettings.asset`, `PairedLensRules.asset`, `TempoRewardRules.asset` |
| Обычные враги | `Assets/Resources/Mobs/Scout.asset`, `Spiral.asset`, `Diver.asset`, `Turret.asset` |
| Феникс | `Assets/Resources/Bosses/Phoenix/Boss/PhoenixBoss.asset` |
| Пасть бездны | `Assets/Resources/Bosses/VoidMaw/Boss/VoidMawBoss.asset` |
| Теневой охотник | `Assets/Resources/Bosses/UmbralHarrier/Boss/UmbralHarrierBoss.asset` |
| Фон, астероиды, туманности | `Assets/Resources/SpaceDepth/Profiles/SpaceDepthProfile.asset` |
| Снаряды и следы игрока | `Assets/Resources/Spells/` |

Внутри Boss: `Shots` — ссылки на выстрелы; `Abilities` — ссылки на способности; `Phases` — выбор атак по HP. Это самостоятельные ScriptableObject, а не встроенные копии. Один Spell и Shot можно назначить нескольким боссам и мобам. Редактирование общей ссылки изменяет её у **всех** владельцев. Для отдельной версии выдели нужный ассет и нажми Ctrl+D; затем назначь копию. То же относится к Vfx и материалам. Папка исходного босса — лишь место хранения, она не ограничивает использование способности.

## Новый босс без кода

1. В Project: **Create → Orbital Rift → Ready-to-edit boss**. Появится `Bosses/Custom/NewBoss.asset` и папка с отдельными `Spell.asset` и `Shot.asset`. Заготовка уже содержит рабочие ссылки.
2. Переименуй файлы. В Boss укажи `DisplayName`, `MaxHp`, `Points`, `WorldSize`, `HitRadius`. У `BossId` уже уникальное значение; при обычном Ctrl+D меняй его вручную.
3. Оставь `UseLegacyPresentation` выключенным: готовые дополнительные эффекты трёх старых боссов предназначены для их исходного рисунка. Для нового рисунка используй `Appearance`.
4. В `Appearance` включи `Enabled`, назначь `Sprite` или `Texture`, настрой `Size`. Назначь кадры, материал и ауру по инструкции ниже. `WorldSize` относится к базовому телу, `Appearance.Size` — к пользовательскому изображению. `HitRadius` независим: подгони его к видимой форме.
5. Открой созданный `Shot.asset`, настрой урон, скорость, залп и визуал. Открой `Spell.asset`, настрой длительность, подготовку, период и движение.
6. `InitialAbility` задаёт начальное состояние и запасную атаку. `InitialStateDuration` — длительность первого состояния. В `Abilities` добавь все используемые способности, в `Shots` их выстрелы.
7. В `Phases` создай, например, две строки: «Ярость», `MaxHealthFraction=0.35`, затем «Обычная», `MaxHealthFraction=1`. Меньший порог должен идти первым. При 30% HP выберется первая строка.
8. В каждой фазе заполни `Attacks`: ссылка `Ability`, `Chance`, `DurationMultiplier`. Строки проверяются сверху вниз: шанс условный, это **не нормализованные веса**. Последнюю доступную обычную атаку поставь с шансом 1. `Cooldown` ограничивает повтор специальной атаки; запасная `InitialAbility` поддерживает бой, если специальные ещё не готовы.
9. Открой `ClassicSequence`, добавь/перемести строку и назначь нового босса в `Boss`. Для быстрой проверки временно поставь его первой строкой. Сохрани и запусти Classic. Затем верни желаемый порядок.
10. Кнопка «Проверить ссылки всех боссов» в инспекторе помогает найти пропущенные ссылки. Новый тип C# / новое значение enum не нужны: бой использует ссылку на BossDefinition. `Archetype` и `AbilityId` оставлены для совместимости исходных боссов и фиксированных кнопок Sandbox; это не список, в который надо регистрировать нового босса или спел. Для нового босса выключи UseLegacyPresentation, а идентичность задавай BossId. Новые произвольные ассеты проверяй через ClassicSequence; исходные кнопки Sandbox не добавляются автоматически.

## Самостоятельная способность и интенсивность

Создание: **Create → Orbital Rift → Bosses → Ability** либо Ctrl+D существующей способности с похожим поведением. Свой PNG не требует нового алгоритма. Совершенно новая механика, которой нет среди Behaviour, потребует программирования.

- `Behaviour=Projectiles`: залпы из `Shot` в течение `Duration`.
- `Dash`: движение из `Movement` и выстрелы из `Shot`; `UseCastMovement` позволяет отдельно настроить подготовку.
- `Summon`: `Summon` задаёт prefab/картинку, HP, число, время жизни, орбиту и выстрелы призванных существ. `SecondaryAbility` позволяет совместить призыв с дополнительной стрельбой.
- `Beam`: количество лучей, длина, безопасный радиус, угловая ширина поражения, скорость вращения, период урона и урон в `Beam`.
- `Roots`: подготовка, ширина захвата и время блокировки в `Roots`.
- `RebirthEgg`: окно уничтожения яйца, HP и восстановление в `Egg`; это поведение босса, не обычного моба.
- `SandboxGravityWell` / `SandboxAura` — существующие визуальные эксперименты Sandbox; `SandboxOnly` запрещает случайно включить их в боевые фазы.

`CastDelay` — подготовка; `Duration` — активное время; `Cooldown` — минимальное время между началами повторных применений; `FirstShotDelay` — задержка первого выстрела после подготовки. `MaxHealthFraction` — доступность атаки по HP. Для мобов способности обходятся по очереди. Базовый Shot моба при активной способности уступает ей стрельбу.

`Shot.FireInterval` меньше → больше залпов в секунду. `ProjectileCount` — число снарядов в залпе. Пример: интервал 0.5 и 3 снаряда дают около 6 снарядов/сек во время активной атаки. Увеличение `Duration` продлевает очередь; увеличение `Cooldown` делает способность реже. Предел числа активных снарядов задаётся в GameRules.

## Выстрел, урон и снаряд

Создание: **Create → Orbital Rift → Bosses → Shot**, либо копия существующего Shot.

- `Damage`: урон одного попадания. HP врагов дробные; клетки здоровья игрока целые, вражеский урон округляется вверх.
- `Element`: стихия. У босса отдельные множители сопротивления; 1 = обычный урон, 0.5 = половина, 1.5 = полтора раза.
- `Speed`: единиц мира/сек; `ScaleSpeedWithPhase` включает рост вместе со сложностью.
- `Lifetime`: через сколько секунд снаряд исчезнет.
- `Pattern`: `AimedFan` — веер на игрока, `Radial` — круг. `SpreadDegrees` — угол между соседями веера.
- `Homing`, `HomingDegreesPerSecond`: наведение и максимальная скорость поворота.
- `PlayerHitRadius`, `ShieldHitRadius`: столкновения; `ShieldCanBlock`, `DestroyOnHit` — блокировка и исчезновение.
- `Prefab`: объект Projectile; пустой у моба использует общий пул. У готовых боссов уже назначены отдельные prefab.
- `VfxPrefab`, `Vfx`, `ImpactPrefab`: общий движок визуала, профиль полёта, эффект попадания. У PNG-снаряда можно сохранить эти следы и заменить только тело через `Appearance`.
- `Sound`, `Shake`: звук и тряска выстрела.

## PNG, материал, покадровая анимация и аура

1. Перетащи PNG в Project, например `Assets/Art/MyBoss/`. Для `Sprite`: в Import Settings выбери Texture Type **Sprite (2D and UI)**, Sprite Mode **Single**, Apply. Для прямого `Texture` можно оставить обычную Texture2D. Прозрачность должна быть в самом PNG.
2. Открой Boss / Mob / Spell / Shot → `Appearance`; включи `Enabled`. Назначь `Sprite` либо `Texture`. Sprite имеет приоритет над Texture; кадры Frames имеют приоритет над обоими.
3. `Material` необязателен. Используй материал, совместимый со SpriteRenderer и прозрачностью (например исходный sprite material проекта). PNG с чёрным непрозрачным фоном не станет прозрачным от смены материала. Материал сам по себе без картинки не создаёт форму.
4. Для анимации: несколько PNG или spritesheet → Sprite Mode Multiple → Sprite Editor → Slice → Apply. Разверни текстуру в Project и перенеси полученные Sprite в `Frames` **в нужном порядке**. Укажи `FramesPerSecond`, например 12; `Loop` повторяет анимацию. Без Loop удерживается последний кадр.
5. Без набора кадров картинку можно оживить: `RotationSpeed` (град/сек), `BobAmplitude/BobFrequency` (качание), `PulseAmplitude/PulseFrequency` (пульсация). Бой ставит эти эффекты на паузу вместе с игровым временем.
6. `Tint` умножает цвет; белый сохраняет PNG. `Size` — размер по большей стороне в мировых единицах.
7. Для ауры назначь `AuraSprite`, при желании `AuraMaterial`, затем `AuraColor` и `AuraSize`. Это визуальная аура; урон от неё не появляется автоматически — для боевого эффекта назначь способность.
8. Appearance способности действует во время её состояния. После возврата к обычной атаке возвращается внешность босса/моба.

У исходных «птенцов» сохранён существующий SolarChickMotion: движение крыльев и пламени из отдельных PNG. Его параметры в `Shot → Vfx → UseBirdMotionSettings`. Пользовательская Appearance заменяет это тело, следы общего SpellVfx остаются.

## Цвета, след, частицы и плавное исчезновение

В `Shot → Vfx`: Core/Glow — тело и свечение; TrailColor — градиент вдоль следа от головы к хвосту; TrailShape — кривая толщины (1 у головы, 0 у хвоста); TrailLifetime — длина следа во времени; TrailWidth — ширина.

`UseLifetimeGradients` включает градиенты изменения по времени жизни: `CoreOverLife`, `GlowOverLife`, `ParticleOverLife`, `ImpactOverLife`; `RibbonOverTrail` — вдоль лент. `AlphaOverLife`, `GlowFade`, `ImpactFade` управляют исчезновением; `ParticleSizeOverLife` — размером частиц. Ось X этих кривых 0..1 означает начало..конец жизни, Y — множитель. Для мягкого конца поставь альфу/ширину 0 в последней точке.

`Style` способности: основные цвета, градиенты линий и их яркость. Внешность исходного феникса дополнительно использует `Boss.Presentation` (BossVfxProfile); профиль влияет именно на эту презентацию.

## Четыре моба: что менять

1. Открой Scout / Spiral / Diver / Turret в Resources/Mobs. Это общие определения для Classic и защиты.
2. `Health`, `Points`, `HitRadius`, `Lifetime`, `Size` — параметры моба. `Sprite` меняет базовую картинку; `Appearance` даёт материал, кадры, пульсацию и ауру.
3. `Movement` выбирает готовую схему: Scout расходится по радиусу, Spiral колеблется, Diver сближается с углом игрока, Turret идёт по окружности. `Radius`, `AngularSpeed`, `RadialAmplitude/Frequency`, `TrackingSpeed` задают её параметры.
4. `Shot` — базовые выстрелы. Открой ссылку для урона, снаряда, PNG, материала, самонаведения и интервала. `Spells` — список самостоятельных способностей.
5. `ShootInClassic` / `ShootInDefense` включают стрельбу и способности по режиму. В защите исходные враги идут к флагману и по умолчанию не стреляют. `DefenseSpeed`, рост скорости, `DefenseWobble/Frequency`, `DefenseAngularSpeed` настраивают их подход.
6. Чтобы получить новый вид моба: Ctrl+D, новый MobId/DisplayName, поменяй рисунок и арсенал; назначь копию в строки Mobs нужной последовательности. Можно использовать существующий Enemy prefab или оставить общий пул.

## Последовательность волн

`GameRules.Classic` и `.Defense` определяют активные последовательности. Строки `Steps` идут сверху вниз; `Loop` повторяет список. Без Loop последняя строка сохраняется для последующих фаз. Номер сложности продолжает расти при повторении списка.

- `Boss` заполнен: появляется этот босс; победа завершает фазу.
- `Boss` пуст: `Waves` обычных волн; количество = `BaseCount + номер фазы × CountPerPhase + номер волны с нуля × CountPerWave`.
- `Mobs`: ссылки, вес `Weight`, начало доступности `FromPhase`, конец `ThroughPhase` (0 = всегда дальше).
- `OrderedMobs=false`: случайный выбор среди доступных строк по весам. Исходные доли врагов сохранены через диапазоны фаз.
- `OrderedMobs=true`: ссылки обходятся по порядку и повторяются; веса и диапазоны в этом режиме не используются. Для нескольких одинаковых врагов подряд повтори строку.
- `InitialDelay`: задержка первой группы Classic. Защита использует один поток мобов на волну и интервалы из GameRules; строки с Boss для неё не предназначены.

Исходный Classic: две обычные фазы → Феникс → две обычные → Пасть → две обычные → Охотник → повтор. В обычной фазе три волны. Перетаскивай строки Steps, чтобы менять порядок, и ссылки Mobs, чтобы менять состав.

## Проверка и сборка

1. Stop → сохранить ассеты → Play → Classic или Защита. Проверяй полный цикл: появление, подготовка, атака, попадание, смерть, следующая волна.
2. `Orbital Rift → Run Gameplay Rules Tests` проверяет формулы и ссылки. `Orbital Rift → Bosses → Validate attacks in Play Mode` запускает расширенную проверку **из Stop** и использует текущие три исходные босса. Это тест исходной конфигурации, а не команда сброса ваших данных.
3. `Orbital Rift → Build Android Debug APK` собирает `Builds/OrbitalRift-debug.apk`.

Сохранения игрока, ник, текущий рейтинг, выбранный корабль и персональные переключатели остаются в PlayerPrefs/сохранении. Их не нужно превращать в общие ассеты игры. Версии сетевого протокола, enum поведения, алгоритмы столкновений и размещение UI — код; ассеты задают данные и настройки готовых механик. Новая механика или новая уникальная форма процедурного эффекта требует изменения кода.
